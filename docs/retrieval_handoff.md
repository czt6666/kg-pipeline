# 检索方案设计交接材料（TCM 知识图谱）

## 1. 一句话背景

中医教材（内科学/基础理论/诊断学三本书）经 OCR → LLM 三元组抽取 → 校验 → 实体对齐 →
建图 → 跨文档合并，产出知识图谱。三本书**各自独立成图，互不跨书合并**（不是一张图）。
现在要在这上面设计检索方案，服务"用户提问 → 找到图里相关的证据/答案"这个场景。

## 2. Schema（`schema/tcm_schema.yaml`）

### 9 个实体类型

| 类型 | 说明 |
|---|---|
| 疾病 | 病名。感冒、消渴、胸痹 |
| 证候 | 一组症状的病理概括，"辨证论治"下的分型标题。风寒束表证、脾虚湿盛证 |
| 症状 | 患者可感/医生可察的单一表现，含舌象脉象。恶寒、苔白腻、脉浮紧 |
| 治法功效 | 治疗原则或方药作用，"治法"（证候用）与"功效"（方药用）共用同一类型 |
| 病因 | 致病因素。寒邪、饮食不节、情志失调 |
| 方剂 | 麻黄汤、参苓白术散 |
| 中药 | 麻黄、桂枝、炙甘草 |
| 性味 | 单个性或味。辛、温、苦、寒 |
| 脏腑经络 | 肺、脾、肾、足太阳膀胱经 |

### 关系（`kind: relational` 才是图里的边；`intrinsic` 挂成头实体 `attributes` 字符串，不建节点）

| 关系 | domain → range | 说明 |
|---|---|---|
| 分型 | 疾病/证候 → 证候 | 疾病或大类证候分出小类证候 |
| 表现为 | 疾病/证候/病因/脏腑经络/症状 → 症状 | 最常见的边 |
| 主症 | 疾病/症状 → 症状 | "总-分"式主要症状 |
| 兼症 | 疾病/症状 → 症状 | 兼见症状 |
| 治法 | 疾病/证候 → 治法功效 | |
| 方用 | 证候 → 方剂 | 代表方 |
| 用药 | 证候 → 中药 | 证候常用药（非方剂配伍） |
| 病位 | 疾病/证候/病因 → 脏腑经络 | |
| 病因 | 疾病/证候/病因 → 病因/症状 | 致病链，可多层 |
| 鉴别 | 疾病/证候/症状 ↔ 同类型 | 对称关系，只存一条 |
| 别名 | 疾病/证候/症状/治法功效/脏腑经络/病因 ↔ 同类型 | 对称关系，只存一条 |
| 组成 | 方剂 → 中药 | |
| 功效 | 方剂/中药 → 治法功效 | |
| 性味 | 中药 → 性味 | **intrinsic**，不建节点，挂 `中药.attributes.性味` |
| 归经 | 中药 → 脏腑经络 | |
| 主治 | 中药 → 症状/疾病/证候 | |
| 加药/减药/加方/换方/变证 | 证候 → 中药/方剂/证候 | 随证加减，**必须携带 `condition`** 字符串说明触发条件 |

**⚠️ 加药/减药/加方/换方/变证 目前基本不在正式产出的图里**（见第 4 节的坑 1）。

## 3. 图里实际有什么

三本书各自一个 `data/work/TCM/merged_{neike,jichu,zhenduan}/`，互不合并：

| | merged_neike | merged_jichu | merged_zhenduan |
|---|---|---|---|
| 源文档数 | 1150 | 363 | 379 |
| 节点数 | 11,531 | 2,194 | 4,874 |

| 整体孤立节点率（无任何边） | **22.18%** | **29.22%** | **15.76%** |

节点类型分布（以 neike 为例，其余两本同形状，占比不同）：症状(5344) > 治法功效(2086) >
病因(1251) > 中药(832) > 证候(816) > 疾病(585) > 方剂(510) > 脏腑经络(94) > 性味(13)。

边类型分布（neike）：表现为(5061) > 用药(3086) > 功效(3049) > 病因(2087) > 治法(1628) >
主症(1320) > 分型(674) > 兼症(591) > 方用(520) > 病位(397) > 别名(328) > 鉴别(176) >
组成(74) > 性味(20) > 归经(2) > 主治(1)。**没有 加药/减药/加方/换方/变证**（见坑 1）。
